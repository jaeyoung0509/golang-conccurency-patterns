# 예제 읽는 법

동시성 코드는 일반 비즈니스 로직처럼 위에서 아래로만 읽으면 놓치는 게 많습니다.
먼저 소유권과 종료 경로부터 따라가야 합니다.

## 먼저 볼 질문

| 질문 | 중요한 이유 |
| --- | --- |
| 각 채널은 누가 만들고 누가 닫는가? | 수명 주기 책임이 어디 있는지 바로 드러납니다. |
| 작업은 무엇이 취소하는가? | 실전 코드라면 보통 `context.Context`로 종료 조건이 명시돼야 합니다. |
| 병렬 실행 수는 제한되는가? | 코드가 깔끔해 보여도 고루틴이 무한히 늘어나면 운영에서는 위험합니다. |
| 출력 순서는 유지되는가, 아니면 의도적으로 느슨한가? | 실무에서는 둘 중 하나가 계약이 되는 경우가 많습니다. |

## 그다음은 테스트를 봅니다

패턴 설명이 완전하려면 테스트가 핵심 보장을 증명해야 합니다.

다음 항목을 확인하세요.

- 동시에 실행되는 워커 수가 제한값을 넘지 않는가
- 첫 오류가 의도대로 다른 작업을 취소하는가
- 호출자 데드라인이 모든 고루틴에 전파되는가
- 부분 실패를 유지할지 버릴지 정책이 분명한가

## Mermaid 다이어그램의 역할

이 사이트의 다이어그램은 장식이 아닙니다.

- 입력/출력 채널의 소유자
- 단계형 처리인지 완전 병렬 처리인지
- 취소와 에러 집계가 어디서 일어나는지

이 세 가지를 먼저 보이게 만들기 위한 장치입니다.
